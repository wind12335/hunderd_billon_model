# 04 · 大模型训练原理全解：从原始文本到更新后的权重

> 目标：把"训练一个大模型"从头到尾讲透——数据→分词→embedding→Transformer 块
> （dense 与 MoE 两种）→损失→反向传播→优化器→checkpoint，以及训练与推理
> （prefill/decode）的本质区别。全部概念都落到两个具体模型上：
> **Llama-3.1-8B**（dense，我们链路测试用的）和 **GLM-4.5-Air-105B**（MoE，最终目标）。
> 文末有"概念 ↔ 本仓库代码"对照表。

---

## 0. 总览：训练到底是什么

一句话：**给定海量文本，反复调整模型权重，使"预测下一个词"越来越准。**

```
┌───────────────────────────────────────────────────────────────────────┐
│ ①数据管线    原始语料 → 清洗/去重 → 分词成 token 序列 → 打包成定长样本  │
│ ②前向        token id → embedding → N×Transformer块 → logits(vocab)   │
│ ③损失        logits 与"下一个真实token"比对 → cross entropy → 标量loss  │
│ ④反向        autograd 沿计算图逆行 → 每个权重得到梯度                  │
│ ⑤优化        AdamW 用梯度更新权重（bf16算 + fp32存）                    │
│ ⑥循环        回到①，做几万~几百万次；期间定期存 checkpoint             │
└───────────────────────────────────────────────────────────────────────┘
```

三个规模感数字（记住这三个，后面所有设计都能对上）：

- **算力**：训练 FLOPs ≈ `6 × 参数量 × token 数`。105B 模型每喂 1 万亿 token
  ≈ 6.3e23 FLOPs——这就是为什么要 128 张卡。
- **显存（静态）**：每参数 bf16 训练态 ≈ `2(权重)+2(梯度)+12(fp32 Adam+主权重) = 16 字节`。
  105B × 16B ≈ **1.68TB**——单机 64GB×8=512GB 都装不下，必须切分（这就是 TP/PP/DP/EP
  存在的理由，也是我们框架搜索的核心约束，`search.py:457` 的公式就是它）。
- **激活**：前向中间产物 ∝ `层数×mbs×seq×hidden`，4096 长度下比权重还大——
  所以要重计算（recompute），只存每层边界，反向时重算。

## 1. 数据预处理与分词

### 1.1 从语料到 token

模型不认识文字，只认识整数 id。转换器是 **tokenizer**（BPE 字节对编码）：

```
"今天天气真不错" --BPE--> [30214, 8891, 447, 205]    ← 词表里的 id 序列
```

BPE 的原理：从字节起家，迭代合并高频相邻对，学出一个"子词表"。
词表大小是模型超参数——Llama-3.1 是 **128256**，GLM-4.5 是 **151552**。
词表直接决定 embedding 矩阵大小（见 §2）和输出层大小（见 §5）。

为什么用子词而不是字/词？字表太小编不出组合含义、每个字信息密度低；
词表太大到无法覆盖（新词、拼写错误、代码、多语言）。子词是折中：
高频词整存、低频词拆件、任何 UTF-8 都能编码（不会 OOV）。

### 1.2 清洗、去重与打包

训练语料的典型处理链（占实际工程量大头，但与并行框架关系较远）：

```
抓取 → 语言检测 → 质量过滤(启发式/小模型打分) → 去重(精确hash/MinHash模糊)
     → 脱敏 → 按文档顺序拼接 → 切成定长(如4096)的样本 → 存成二进制索引
```

"打包"(packing)：把长短不一的文档首尾相接填满定长窗口。是否用
document mask（阻止样本内跨文档注意）是训练质量与效率的权衡点。

### 1.3 我们链路测试里的数据是什么

launch 脚本里 `--mock-data --tokenizer-type NullTokenizer --vocab-size 32000`：
**没有语料、没有分词器**，每个 batch 直接随机采样 token id。
所以 loss 从 11.2（≈ln(32000)·上限量级，纯乱猜）起步、快速降到 3 附近
（模型学会"背分布噪音"的过拟合形态）。**数值无意义，链路有意义**：
数据管线的位置、形状、dtype 全部与真实一致，等 M3 换真 tokenizer/数据集时
上游代码零改动。

## 2. Embedding：从 id 到向量

第一步是把每个 token id 变成稠密向量。实现是一张**查表**：

```
E ∈ [vocab_size, hidden]        Llama-8B: [128256, 4096] ≈ 5.25亿参数, bf16 约1.05GB
x = E[token_id]                 一次前向只是查行，无乘法
```

为什么查表而不是 one-hot×W？数学上等价（one-hot 只有一个 1），
查表把 O(vocab×hidden) 的乘法变成一次内存读取。

**并行为什么先找上 embedding**：它是参数最多的"单层"之一，且按词表维切分
天然无通信（前向各自查到非零行 allreduce，反向各更新自己的行）——
这就是 ParallelPlan 里 `embedding=vocab_shard` 的含义。参考实现
`tools/run_pytorch_llama_tp_dp.py:1105`（HfLlamaForCausalLm）里能看到完整写法。

---

## 3. 位置编码：RoPE

Transformer 的 attention 本身"不分先后"（打乱序列顺序、attention 结果集合不变），
必须额外注入位置信息。现代模型（Llama/GLM 都是）用 **RoPE 旋转位置编码**：

```
把每个 head 的向量两两配对，视为复数；位置 p 的 Q/K 旋转角度 p·θ
→ Q·K 内积自然只依赖 (i−j) 相对位置；无学习参数；外推性较好
```

两个我们模型里的真实参数：Llama-3.1 `rotary_base=500000`（θ 的基频，
大 base 利于长序列，生成脚本里 `--rotary-base 500000` 直接来自 spec）；
GLM-4.5-Air `partial_rotary_factor=0.5`——**只旋转 head_dim 的一半**（前 64 维转、
后 64 维直通），牺牲一点位置分辨换长度外推能力。

## 4. Dense Transformer 块（Llama 型）：模型的心脏

Llama-3.1-8B 全部结构 = embedding + **32 个相同的块** + 输出头。每个块：

```
x ─→ RMSNorm ─→ Attention(GQA) ─→ + ─→ RMSNorm ─→ MLP(SwiGLU) ─→ + ─→
│_______________________│                    │______________________│
        残差连接                                     残差连接
```

### 4.1 RMSNorm（为什么不是 LayerNorm）

```
y = x / sqrt(mean(x²)+ε) · γ        ← 只有缩放，没有均值中心化，没有 β
```

效果与 LayerNorm 相当，少一次均值计算、少一半参数，更适合大 batch 矩阵运算。
每个块两处（attention 前、MLP 前，Pre-Norm 结构——残差主干上是恒等映射，
这是深层网络可训练的关键）。

### 4.2 Attention 与 GQA（用 Llama-8B 的真实数字）

设 `seq=4096, hidden=4096, 32 个 Q 头 × head_dim 128, 8 个 KV 头`（GQA）。

```
X [4096, 4096]
 ├─Wq [4096, 4096]→ Q [4096, 32×128]   拆成 32 个头
 ├─Wk [4096, 1024]→ K [4096,  8×128]   只有 8 个 KV 头!
 ├─Wv [4096, 1024]→ V [4096,  8×128]
 每头: scores = Q_h·K_hᵀ/√128 → [4096,4096]
       A_h = softmax(scores)（因果mask:只看过去）
       out_h = A_h·V_h → [4096,128]
 └─Wo [4096, 4096]→ 拼回 32 头投影输出
```

- **GQA（分组查询注意力）**：32 个 Q 头共享 8 组 KV 头（每 4 个 Q 头用一组）。
  KV 参数量与推理 KV cache 直接缩 4 倍，质量损失很小——训练省显存、推理省内存带宽，
  是"性价比最高的架构改动"。GLM-4.5-Air 更激进：96 Q 头 / 8 KV 头。
- **因果 mask**：位置 i 只能注意 ≤i。这一行 mask 就是"语言模型只能用过去预测未来"的数学形态。
- **scores 矩阵 [32头, 4096, 4096] fp32 ≈ 2GB**——绝不能物化！实际用
  **Flash Attention**：分块计算 softmax（在线归一化），显存 O(seq) 而非 O(seq²)。
  我们的栈里它是 TE/ROCm 的 HIP kernel（框架层只见 `core_attention` 调用）。
- **TP 切在头上**：32 头 / TP4 = 每卡 8 个 Q 头 + 2 个 KV 头，Wq/Wk/Wv/Wo 按头切成 4 份——
  这就是 `_valid_tp_sizes` 要求 TP 整除头数的原因，也是
  `run_pytorch_llama_tp_dp.py:885`（HfLlamaAttention）演示的 head_shard。

### 4.3 MLP 与 SwiGLU

```
h  = SiLU(X·Wgate) ⊙ (X·Wup)      三次 GEMM:
out = h·Wdown                        Wgate/Wup [4096,14336], Wdown [14336,4096]
```

为什么三个矩阵而不是两个（普通 FFN）？gate 分支学"放行多少"、up 分支学"内容什么"，
逐元素乘做门控——经验上同等参数下比两层 FFN 质量更好。代价是三个矩阵，
**切分必须"列切前两个、行切第三个"**（colrow_shard）：前两个按输出维切（每卡算自己
那段 14336/TP 的 gate·up，无需通信），最后一个按输入维切（结果 allreduce 一次）。
这就是 ParallelPlan 里 `mlp=colrow_shard` 的精确含义。

### 4.4 参数对账（8B 是怎么来的）

```
每层 attention: 16.78M(Q)+4.19M(K)+4.19M(V)+16.78M(O)        ≈ 42M
每层 MLP:       58.72M×3                                       ≈ 176M
每层合计 ≈ 218M × 32 层 ≈ 6.98B
embedding + lm_head(不共享) 0.525B×2 ≈ 1.05B
───────────────────────────────────────────── ≈ 8.03B ✓
```

## 5. 输出头与损失：预测下一个词怎么变成一个数字

```
h [4096, 4096] --lm_head [4096, vocab]--> logits [4096, 128256]
labels = 输入右移一位（t1..tn）        ← teacher forcing
loss = CrossEntropy(logits, labels)    ← 每个位置都算，取平均
```

- **teacher forcing**：训练时每个位置都拿**真实**的上文（不是模型自己生成的），
  所以一条 4096 的序列一次前向同时产生 4095 个训练信号——**这是训练和推理
  的根本区别**（§11 展开）。
- logits 矩阵 [4096×128256] ≈ 1GB（bf16），也切：`lm_head=vocab_shard`，
  每卡算自己那段词表的 logits，用 log-sum-exp 技巧无通信地拼出全局 softmax——
  参考实现 `_VocabParallelCrossEntropy`（`run_pytorch_llama_tp_dp.py:184`）。
- loss 是**全 vocab 上 softmax 的负对数似然**：`-log p(正确token)`。
  随机初始化时 ≈ ln(vocab)：我们 mock 的 ln(32000)≈10.4，起步 loss 11.2 对得上。

## 6. MoE Transformer 块（GLM-4.5-Air 型）：把"每一层都会算"改成"每层只激活一小撮专家"

### 6.1 结构差异一览

GLM-4.5-Air：46 层 = **第 0 层 dense + 第 1-45 层 MoE**（首层用 dense 是主流 MoE
模型惯例：底层变换相对简单、MoE 收益低）。MoE 层 = **attention 不变（仍是 GQA）**，
只有 MLP 换成"专家团"：

```
dense 层:   MLP(X)                              ← 每 token 都全量算
MoE 层:     Y = Shared(X) + Σ_{i∈top8} g_i·E_i(X)
            Shared = 一个普通 SwiGLU（永远激活）
            E_i    = 128 个专家 SwiGLU 之一, 各自 [4096→1408→...→4096]
            g_i    = router 给的权重（softmax 后 top-8 的归一化分数）
```

具体数字（可对账出 105B）：

```
单个专家:  3 × 4096 × 1408                    ≈ 17.3M 参数
每 MoE 层: 128 专家×17.3M + 共享17.3M + router 4096×128 ≈ 2.24B
45 个 MoE 层                                 ≈ 100.6B
+ 46 层 attention + 1 个 dense MLP + emb/lm_head(151552×4096×2)≈1.24B
───────────────────────────────────────────── ≈ 105B ✓
```

**MoE 的本质**：参数量（容量）与每 token 计算量（成本）解耦。
每 token 只过 9 个 MLP（8 路由 + 1 共享）≈ 156M 参数的 MLP 计算，
却拥有 100B 级的参数容量。代价：全部 128 个专家的参数必须**驻留**显存——
计算省了，存储一点没省，还更难切。

### 6.2 Router 与 top-k

```
logits = X·W_router [4096, 128]      ← 唯一的、极小的全连接
probs  = softmax(logits)
(top8 的下标, top8 的概率) = topk(probs, 8)
g_i    = top8概率 / Σtop8概率         ← 归一化
```

**训练上的微妙点**：top-k 选专家是**不可导**的离散操作。梯度只能流过
"被选中的 (token, expert) 对"的 g_i 和专家权重；没被选中的专家这一步拿不到梯度。
router 因此会自我强化（赢者通吃、雪崩到少数专家）——需要下面的辅助损失。

### 6.3 负载均衡辅助损失（aux loss）：MoE 训练的第一公民

Switch Transformer 式经典形式：

```
f_i = 分配到专家 i 的 token 比例        (硬计数)
P_i = router 给专家 i 的平均概率        (软概率)
L_aux = α · N · Σ f_i·P_i              N=专家数
完全均衡时 L_aux = α·1（最小）；越偏斜越大
```

直觉：f_i 不可导、P_i 可导，乘积把"实际负载"的梯度灌回 router 的概率输出，
逼迫它把 token 摊开。总损失 = `L_ce + α·L_aux`（α 常取 0.01 量级）。
不做这件事，训练后期会塌缩成"128 个专家只剩几个在干活"，
MoE 的容量优势归零。**这是 MoE 训练与 dense 训练在损失函数上的唯一结构性差异。**

### 6.4 Token Dispatcher 与专家并行（EP）：MoE 的通信形态变了

dense 层的并行通信是"**权重分片间的 allreduce**"（TP）；
MoE 层引入了完全不同的通信原语——**token 在专家间搬家**：

```
EP=8 时 128 专家分到 8 卡, 每卡 16 个本地专家
① all-to-all #1: 各卡把"路由到别卡专家"的 token 发出去      (跨节点RCCL)
② 每卡对 16 个本地专家分别批量计算（不成批的专家低效!）
③ all-to-all #2: 结果按 token 送回原卡, 加权求和 + 共享专家输出
```

配套机制：**capacity factor**（每个专家的 token 槽位上限 = 均值×系数，防雪崩），
溢出 token 被 drop 或残差直通（训练动态稳定性的关键旋钮）。
Megatron 对应模块：`moe/router.py`（topk+aux loss）、`moe/token_dispatcher.py`
+ `moe/fused_a2a.py`（两次 all-to-all）、`moe/experts.py`（批量 GEMM）、
`moe/shared_experts.py`、`moe/moe_layer.py`（总装）。

**EP 与 DP 的关系**（FRAMEWORK_GUIDE 的约束"EP 整除 DP"的出处）：
世界 = TP×PP×DP，EP 是在**同一份模型复制的 DP 维度内部**再切专家。
128 卡 GLM 方案 TP8/PP2/DP8/EP8：TP×PP=16 份模型"残缺副本"，DP8 份数据副本，
专家在每组的 8 个 DP rank 间再散开——所以 EP ≤ DP 且整除。

### 6.5 MoE vs dense 训练差异清单

| 维度 | dense（Llama） | MoE（GLM） |
|---|---|---|
| 损失 | CE | CE + **aux load-balance loss** |
| 每层计算 | 恒定（全参数） | 每 token 只 9/129 MLP（计算稀疏） |
| 显存 | 参数即计算驻留 | **参数≫计算**，128 专家全驻留 |
| 通信 | allreduce（TP/DP） | + **all-to-all ×2**（EP，token 搬运） |
| 优化器状态 | 与参数等比 | 与参数等比（105B×12B 的 Adam 状态是显存大头） |
| checkpoint | 按 TP/PP 分片 | 还要按 **EP 分片**（专家归属 rank） |
| 风险点 | 训练稳定性 | 路由塌缩 / token drop / 专家间负载不均 |
| 搜索空间 | TP×PP×DP | TP×PP×DP×**EP**（我们 search_max_ep 的意义） |

## 7. 反向传播：autograd 在做什么

前向是"函数求值"，反向是"求梯度"。PyTorch 的 autograd 把前向算子记录成
**计算图**（DAG），backward 从 loss 出发按**链式法则**逆行，每个中间量只算一次：

```
loss → d loss/d out → 逐算子局部导数回传 → d loss/d W（每个权重一个梯度张量）
```

两点在并行训练里必须理解：

**① 梯度与参数形状相同、显存翻倍**——这就是"16 字节/参数"里的 `+2B`。
（Adam 状态的 +12B 见 §8。）

**② 并行切分下，autograd 的"局部导数"不足以算完全局梯度**，需要在图里显式插
通信算子——Megatron 的 f/g 算子（参考实现摊开在
`run_pytorch_llama_tp_dp.py:151/:168`）：

```
前向 g = _CopyToTensorParallelRegion:    identity（什么都不做）
反向       → allreduce（把各卡的梯度份额加起来）
前向 f = _ReduceFromTensorParallelRegion: allreduce（把各卡的输出份额加起来）
反向       → identity
```

**一句话：并行训练的前向图里，每一个"免费的 identity"都对应反向的一次集合通信
（反之亦然）。** 我们日志里每个 iteration 的 DP allreduce 跨节点流量，就是这类算子
在跑（`training.py:2162` 的 train_step 内）。

（区分两个"重计算"：**梯度检查点 activation recompute**——训练时丢弃中间激活、
反向时重算，省显存换时间，生成脚本里 `--recompute-granularity full` 是它，
对应显存公式里激活的 0.35 压缩因子；与推理的 KV cache 无关，见 §11。）

## 8. 优化器与混合精度：梯度怎么变成新权重

### 8.1 从 SGD 到 AdamW

```
SGD:     W ← W − lr·g
+动量:   v ← β1·v + g;      W ← W − lr·v           （平滑抖动）
Adam:    m ← β1·m+(1−β1)g;  v ← β2·v+(1−β2)g²      （逐参数自适应步长）
         m̂=m/(1−β1ᵗ); v̂=v/(1−β2ᵗ)
         W ← W − lr·m̂/(√v̂+ε)
AdamW:   再加解耦权重衰减 W ← W−lr·λW               （λ=weight decay）
```

直觉：loss 曲面各方向陡峭程度差几个量级，Adam 给"一直很陡"的参数小步长、
"一直平缓"的参数大步长。大模型标配 **AdamW(β1=0.9, β2=0.95, wd=0.1)**——
正好是生成脚本里 `--adam-beta1 0.9 --adam-beta2 0.95 --weight-decay 0.1` 的来源。
另有 `--clip-grad 1.0`：全局梯度范数超过 1 就整体缩放（防个别坏 batch 引爆）。

### 8.2 混合精度：为什么是 16 字节/参数

```
前向/反向:  bf16   (权重2B + 梯度2B)        ← 快、省、动态范围大
主权重:     fp32   (4B)                      ← 累积小更新不丢精度
Adam m,v:   fp32   (8B)                      ← 二阶矩对精度敏感
────────────────────────────────────────────
静态合计   2+2+4+8 = 16 B/参数
```

bf16 相比 fp16：指数位与 fp32 相同（动态范围大），不需要 loss scaling——
DCU/HIP 栈上 bf16 是舒适区。这就是 `_estimate_memory` 公式里
`参数×2 + 梯度×2 + Adam×12` 的完整含义。

### 8.3 分布式优化器：128 卡怎么分摊那 12 字节

105B 的 Adam+主权重 ≈ 1.26TB，复制 8 份（DP8）不可行。
Megatron `--use-distributed-optimizer`（ZeRO-1 思想）：**优化器状态按参数分片
到 DP 组各卡**，每卡只为自己的 1/dp 参数保存 fp32 状态：

```
反向后: 梯度 reduce-scatter（每卡拿到自己分片的完整梯度）
        各卡更新自己分片的 fp32 主权重
        权重 bf16 allgather 回全量（TP/PP 各卡拼出完整模型）
```

通信量与传统 DP allreduce 同阶，显存降为 1/dp——这是 GLM-128 卡方案里
"24.6GB/卡"能算进预算的前提。

## 10. Checkpoint：训练状态的快照与恢复

保存内容远不止权重：**模型分片 + fp32 主权重 + Adam m/v + 迭代号 + RNG 状态 +
dataloader 位置 + 参数结构签名**，TP/PP/EP 每个维度都要分片落盘
（`save_checkpoint_and_time`, training.py:2773）。恢复时必须**同一并行布局**重聚

这就是路线图 M2 专项（把 save-interval 调小验证保存+断点恢复）存在的原因。

## 11. Prefill vs Decode：训练和推理到底差在哪

### 11.1 先说结论

| | 训练 | 推理-prefill | 推理-decode |
|---|---|---|---|
| 每步输入 | 完整 4096 序列（真实上文） | 完整 prompt | **1 个 token** |
| 前向方式 | 全序列一次并行（=teacher forcing） | 全序列一次并行 | 逐 token 串行 |
| KV cache | **不需要**（每步都是新序列） | 生成并写入 | 读取并追加 1 行 |
| 计算形态 | GEMM 密集（算力瓶颈） | GEMM 密集（算力瓶颈） | 向量/带缓存 attention（**显存带宽瓶颈**） |
| 目标 | 拿梯度 | 拿第一个新 token 的分布 | 每步 1 个 token |

### 11.2 KV cache：decode 之所以成立

自回归生成第 n 个 token 时，attention 要看全部历史 K/V。若每步都重算全部历史，
代价 O(n²) 次。**KV cache 把每层历史的 K/V 存下来，每步只算新 token 的 Q/K/V 一行，
追加进缓存**——每步代价降为 O(n)。

大小公式：`2(K,V) × seq × kv_heads × head_dim × 精度 × 层数`。
Llama-8B、seq 8192、bf16：2×8192×8×128×2B×32层 ≈ **1.07GB/条序列**——
GQA（8 而非 32 个 KV 头）把它压小了 4 倍；没有 GQA 是 4.3GB。
这就是 GQA 对推理的第二重价值（§4.2 第一重是训练省参）。

### 11.3 为什么 decode 是显存带宽瓶颈

decode 每步要**读完全部权重**（8B×2B=16GB）只产出 1 个 token——算术强度
（FLOPs/字节）极低，卡算力闲置、内存带宽打满。应对：大 batch 聚合（连续批处理）、
PagedAttention、量化、投机解码。prefill 则是规整大 GEMM，算力瓶颈——
所以服务系统把两阶段分开调度（chunked prefill 等），二者混合时互相干扰。

### 11.4 MoE 推理的特殊性

每 token 只激活 8+1 个专家 → 单 token 计算量只相当于 ~0.5B dense 模型的 MLP 部分
（吞吐极佳），但 105B 权重必须驻留（显存/多卡 EP 服务）。MoE 是"推理友好、
部署昂贵"的架构；GLM-4.5-Air 选 top-8 也是吞吐与时延的折中。

### 11.5 常见误解澄清（对照我们训练）

- 训练日志里的 iteration 慢（285s）与 decode 无关——那是 mock/小 batch/INFO 日志开销；
- `--recompute`（训练激活重计算）≠ KV cache（推理历史缓存），只是都叫"重用计算"；
- 训练永远不需要 KV cache：teacher forcing 下目标序列已知，一次前向出全部位置的 loss。

## 13. 一页收束

- **dense**（Llama）：每层全参数算，训练 = CE 损失 + allreduce 通信，显存压力靠 TP/PP/重计算。
- **MoE**（GLM）：MLP 换专家团，每 token 只激活 top-8+共享；多两个新事物——
  aux loss（防路由塌缩）与 all-to-all（token 搬家）；显存压力更大，靠 EP+分布式优化器。
- **训练 vs 推理**：训练是 teacher forcing 全并行前向拿梯度（不需要 KV cache）；
  推理分 prefill（一次并行、算力瓶颈）与 decode（逐 token、显存带宽瓶颈、靠 KV cache）。
- **我们框架的位置**：以上所有"怎么切、怎么组网、怎么估算显存"的决策由
  `search.py` 自动完成（文档 02/03），"怎么训"由 Megatron 完成，"怎么算"由
  torch/RCCL/DTK 完成（文档 01）。
