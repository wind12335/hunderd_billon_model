# 01 · 框架模块地图与语言栈

> 回答的问题：这套框架的代码分几个模块？每个模块用什么语言？我们写的代码在哪一层，
> 下面还压着哪些不是我们写、但必须理解的层？

---

## 1. 先给结论：语言构成（实测统计）

```
本仓库自有代码（thousand_model，不含 Megatron-LM-das 参考仓库）：
  Python : 7751 行   （autoparallel/ megatron_mvp/ tools/ examples/）
  Bash   : 1063 行   （scripts/ + 运行时生成的 launch_*.sh）
  C++/CUDA/HIP/Triton/MLIR : 0 行     ← 我们不写任何算子/内核代码
```

**我们的框架是纯 Python + Bash 的"规划与编排层"**。它不做任何矩阵乘法、不写任何 kernel——
所有数值计算都委托给下层的工业级组件。这是刻意设计（也是组会汇报的要点）：
框架的价值在"决策"（怎么切分、怎么编排），不在"计算"（怎么乘得快）。

## 2. 完整语言栈：从我们的代码到硅片

```
┌─────────────────────────────────────────────────────────────────────┐
│ L7  我们的框架          Python + Bash                                │
│     autoparallel/ megatron_mvp/ tools/ scripts/                     │
│     作用：模型探测→并行策略搜索→显存验证→生成脚本→多机编排            │
├─────────────────────────────────────────────────────────────────────┤
│ L6  Megatron-LM 0.18.2 Python（~10万行）                            │
│     + hcu_megatron 补丁层（Python，导入期替换 88 个函数）            │
│     + Megatron-Bridge（Python，HF↔Megatron 结构映射）               │
│     作用：训练循环、并行算子的"指挥"、数据管线、优化器、checkpoint   │
├─────────────────────────────────────────────────────────────────────┤
│ L5  PyTorch 2.7.1+das   Python 前端 + C++ 核心（ATen/Dispatcher）    │
│     作用：张量抽象、autograd 自动微分、nn.Module、torch.distributed  │

│     节点内走 P2P/IPC（片间互联），节点内跨卡走 xdp 链路，            │
│     节点间走 NET/Socket（TCP，我们日志里看到的 via NET/Socket/0）    │
├─────────────────────────────────────────────────────────────────────┤
│ L2  Transformer Engine 2.10   C++/HIP 内核 + Python API             │
│     作用：融合的归一化/Softmax/GEMM 内核、fp8/bf16 混合精度支持      │
├─────────────────────────────────────────────────────────────────────┤
│ L1  DTK (/opt/dtk)      海光版 ROCm 工具链：hipcc 编译器、           │
│                         rocblas/miopen 等运行时库（全 C++ 编译产物） │
├─────────────────────────────────────────────────────────────────────┤
│ L0  硬件 BW1000 (DCU)   64GB HBM2e，HIP/ROCm 指令集                 │
└─────────────────────────────────────────────────────────────────────┘
```

### 关于 Triton 与 MLIR（常被问到，如实回答）

- **MLIR**：本栈**完全没有用**。MLIR 出现在 Alpa/TVM 类"重编译器"式自动并行框架里；
  我们的"编译器"是**符号规划+代码生成**——中间表示是 JSON（`coarse_ir.json`），不是编译器 IR。
- **Triton**：环境里装了（torch 2.7 自带 pytorch-triton），`torch.compile` 会生成 Triton kernel；
  但我们的生成脚本里**显式禁用**了（`TORCH_COMPILE_DISABLE=1`、`TORCHDYNAMO_DISABLE=1`）——
  训练稳定性优先，不用即时编译。所以 Triton "在场但 unemployed"。

### 一句话记住分工

> **L7 决定"怎么切"，L6 决定"怎么训"，L5 提供自动微分，L3-L4 真正搬数据做乘加，
> L0 出浮点结果。** 我们所有工作都在 L7，但排障时必须能看懂 L6/L3 的日志
> （昨天的 NCCL WARN 风暴就是 L3 的话）。

### 三个包的依赖方向（编译器式分层）

```
examples/autoparallel_multinode_train.py   （CLI 入口）
        │ 只调用
        ▼
autoparallel/（前端：Config → compile → lower）
        │ 只调用
        ▼
megatron_mvp/（中端：detect/search/render——不知道"脚本"为何物）
        │ 产物（JSON + .sh）
        ▼
tools/ + scripts/（执行层：把产物在真实集群上跑起来）
        │
        ▼
Megatron-LM + hcu_megatron + RCCL + DTK（L6→L0）
```

依赖是**单向的**：中端不知道执行层的存在，前端不知道中端内部函数——
这就是为什么昨天在集群上调启动问题时，编译器前端一行未改。
